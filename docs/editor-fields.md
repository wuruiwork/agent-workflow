# 流程编辑器字段说明

> 本文件由 `editor/fields.mjs` 生成；修改说明后运行 `node scripts/gen-field-docs.mjs`。
> 编辑器里鼠标移到字段标题上也会显示同样的说明。

## 流程信息

### 流程名

流程的唯一标识，只能用小写字母、数字和连字符。

### 产物目录

流程文档存放的位置，例如 docs/specs/current；第一阶段开始就在这里写文档。

### 描述

一句话说明这个流程做什么，方便在流程列表里区分。

### 归档目录

流程结束后文档归档到的目录，通常是产物目录去掉 current，例如 docs/specs。

### 动作槽位

git 动作可以插入的位置：task_end（skill 阶段内每完成一个任务）、stage_end（每个阶段结束时）和 finish（流程结束时）。不需要调整时保持默认。

### 流程版本

2 = 单链流程；3 = 图流程，支持条件分支、并发和回环。编辑器里用「转为图流程」从 v2 升级到 v3。

### 连线起点

这条边从哪个阶段出发；起点阶段完成并满足条件后激活。

### 连线终点

这条边指向哪个阶段；终点阶段根据 join（any/all）决定何时执行。

### 连线条件

always = 源阶段完成即走；pass / fail = 按源阶段的产物门禁结果分支；status = 按产物 frontmatter 的 status 值分支。

### 条件状态值

连线条件为 status 时，产物 frontmatter 的 status 必须等于这个值才走这条边。

### 回环上限

这条边最多被穿越多少次。回环必须至少有一条边设置上限，防止无限循环；留空表示不限。

## 阶段

### 阶段标识

阶段的唯一名字，例如 brief、implement；项目配置里的动作绑定按这个名字匹配。

### 类型

doc = 按文档执行的人工/写作阶段；skill = 调用一个已有 skill 的阶段。

### 引用

doc 类型填阶段文档路径（如 stages/brief.md）；skill 类型直接从仓库已有 skill 里选择。

### 产物文件

这个阶段完成时要生成的文件名，例如 00-brief.md；留空表示没有固定产物。

### 状态门禁

产物 frontmatter 里必须出现的 status 值，例如 approved、done、pass。

### 人工确认

勾选后，这个阶段的产物必须由你明确确认。doc 阶段确认后改 status；skill 阶段先执行设计轮，确认后再重入实现轮。

### 动作槽位

这个阶段要触发哪些 git 动作槽位，例如 stage_end；具体执行 commit 还是 push 由项目配置决定。

### 汇合方式

仅 v3 图流程：any = 任一入边激活就执行（条件分支汇合）；all = 所有入边都激活才执行（fan-out 汇合）。

## 阶段动作（git）

### 提交

阶段结束后把改动 git commit。提交信息按阶段类型自动生成。

### 推送

阶段结束后推到远端。推送不等全部验证通过，方便中途保存进度。

### 合并请求

调用 glab / gh / gitee 创建 MR 或 PR，按项目配置的目标和条件执行。

### 提交类型

这个阶段提交时用的前缀，例如 feat、fix、docs；auto 表示按改动内容自动判断。

## 项目配置

### 启用流程

这个项目允许使用哪些流程。没勾选的流程不会被 flow-runner 提供。

### 保留最近 N 个

至少保留最近 N 个已归档 feature；不在最近 N 个且超过保留天数的记录才会进入清理候选。

### 保留最近 N 天

至少保留最近 N 天内归档的 feature；与 keep_latest 取并集。

### 至少保留 N 个

无论其他条件如何，已归档 feature 至少保留 N 个。

### 清理模式

report = 只报告；ask = 列清单等你确认；auto = 按策略自动删除。

### 推送远端

git push 的目标远端，通常是你的 fork，例如 origin。

### 上游远端

团队主仓库的远端名，例如 upstream；用于同步和跨项目 MR。

### 默认分支

主分支名，通常是 main。在主分支上提交会被拒绝，需要先切分支。

### 在主分支上

refuse = 直接拒绝提交；create = 自动切一个新分支。

### 分支命名规则

允许提交的分支名正则，例如要求以 feat/、fix/、docs/ 开头。

### 分支来源

自动建分支时从哪个引用开始，例如 upstream/main。

### 禁止提交的路径

敏感或临时文件，例如 .env、.tmp、.skillgate/phase；提交时会自动排除。

### scope 映射

按阶段给 commit 加 scope，每行 stage: scope，例如 verify: test。

### 推送远端（动作）

push 动作实际使用的远端名，一般和推送远端一致。

### 首次推送设置 upstream

新分支第一次推送时自动执行 git push -u。

### 合并请求目标

可以配置多个目标：工作分支 → fork main；fork main 满足条件时 → 上游 main。

### 目标标识

给这个 MR 目标起个名字，例如 review、sync-upstream，方便区分。

### 源分支

从哪里合并：current_branch 表示当前工作分支，也可以写 origin/main。

### 目标分支

合并到哪里，例如 origin/main；决定 MR 创建在哪个项目。

### 触发条件

总是创建、领先 N 个提交时创建，或主干空闲 N 天时创建；可以组合。

### 标题模板

MR 标题模板，{ahead} 会替换成领先的提交数。

### 描述章节

MR 描述里要包含的小节，例如变更目的、影响范围、测试结果。

## Skill 与高级

### 名称

skill 目录名，只能包含小写字母、数字和连字符。

### 描述

告诉 agent 什么时候使用这个 skill，写得越具体越容易被正确调用。

### 正文

SKILL.md 的 Markdown 内容，写执行步骤和边界。

### 导入文件夹

导入已有的 skill 目录，会保留 references、scripts 等子目录。

### 测试命令

验证阶段执行的测试命令，例如 uv run pytest -q；留空会使用占位命令。

### 高级预览

这里的内容由上面的表单自动生成，只读；需要备份或排查时再看，不需要手改。
